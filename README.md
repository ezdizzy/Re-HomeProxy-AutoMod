# Ravnex

**Own the Route.**

Многоядерная прокси-платформа для OpenWrt: VPN-подписки, обход DPI без VPN, автоматизация,
мониторинг и диагностика — всё из веб-интерфейса LuCI, всё локально на роутере.

## О проекте

**Ravnex** — это система управления сетевым трафиком на роутерах OpenWrt/ImmortalWrt, которая объединяет:

- **два прокси-ядра на выбор** — [hiddify-core](https://github.com/hiddify/hiddify-core) (форк sing-box, по умолчанию)
  и [sing-box-extended](https://github.com/shtorm-7/sing-box-extended) / компактный
  [sing-box-extended-lite](https://github.com/MANCrimSon/sing-box-extended-lite) для устройств с малым объёмом flash;
- **два движка обхода DPI без VPN** — [Zapret 2](https://github.com/bol-van/zapret2) (nfqws2) и
  [ByeDPI](https://github.com/hufrea/byedpi) (ciadpi) с каталогом стратегий, лабораторией подбора и автопилотом;
- **обучающий движок автоматизации**, который сам находит заблокированные ресурсы и маршрутизирует их;
- **горячий резерв узлов** (Hot Swap), **гонка DNS-серверов** (MultiDNS),
  **родительский контроль**, **Telegram-бот управления** и **самообновление приложения**.

Вся логика работает на **ucode** — нативном интерпретаторе OpenWrt, — поэтому приложение экономно расходует
RAM и не требует внешних сервисов: веб-интерфейс не обращается ни к каким CDN, все графики рисуются локально,
а проверка обновлений выполняется только по вашему запросу.

## Почему Ravnex

- **Обход блокировок без подписки.** Zapret 2 и ByeDPI работают на самом роутере: YouTube, Discord
  и тысячи сайтов открываются обычным трафиком с десинхронизацией DPI. Прокси-узел нужен только
  для приватных маршрутов и ресурсов, которые не пробиваются и так.
- **Никогда не оставляет без интернета.** Сбой ядра, движков или firewall-цепей означает прямой
  проход трафика, а не чёрный экран; при рабочем WAN у вас всегда остаётся хотя бы российский
  интернет — инвариант, проверенный каскадом отказов живьём. Аварийная кнопка «Восстановить
  интернет» возвращает прямое соединение в один клик.
- **Отказ — не простой.** Hot Swap держит постоянно проверяемые резервы основного узла и
  переключается за секунды без рестарта ядра; сторожа сами чинят сломавшуюся стратегию,
  а автопилот по расписанию следит за качеством.
- **Диагностика честная.** Вердикты строятся из реальных замеров; хост, недостижимый ни с одной
  стратегией, исключается из оценки, а не красит всю таблицу; различия в пределах шума помечаются.
- **Экономичен.** Управляющая логика — ucode, без внешних рантаймов; для слабых устройств —
  компактная UPX-сборка ядра, lite-режимы демонов и профили Авто/Лёгкий/Сбалансированный/
  Производительность.

## Как идёт трафик

Соединения классифицируются таблицами **nftables** и уходят по контурам — без лишнего транзита
через пользовательское пространство:

| Контур | Механизм | Что идёт этим путём |
|---|---|---|
| **Напрямую** | маршрутизация мимо перехвата, нулевая надбавка | доверенные ресурсы: Россия, банки, госуслуги, локальные сети |
| **Zapret 2** | [`nfqws2`](https://github.com/bol-van/zapret2) — пакетная десинхронизация в NFQUEUE | YouTube, Discord и другие ресурсы открываются **без VPN и без подписки**, быстро и с российским регионом |
| **ByeDPI** | [`ciadpi`](https://github.com/hufrea/byedpi) — локальный SOCKS-десинхронизатор | 47 готовых пресетов и тестер стратегий |
| **Прокси-ядро** | hiddify-core / sing-box-extended | заблокированные и приватные маршруты через ваш узел/подписку: VLESS (Reality/XHTTP), Hysteria2, VMess, Trojan, Shadowsocks, WireGuard/**AmneziaWG**, SSH, NaiveProxy, Mieru и другие |
| **Smart DNS** | [mosdns](https://github.com/IrineSistiana/mosdns) — гонка всего пула на каждом запросе | раздельные пулы plain/secure DNS, контроль качества, автоисключение мёртвых серверов |

## Принципы работы

- **Всё исполняется на роутере.** Фоновые демоны написаны на **ucode** — штатном интерпретаторе
  OpenWrt — и потребляют единицы мегабайт RAM; Go используется точечно, для нативных помощников
  (батч-пробы, захват SNI). Веб-интерфейс общается с демоном через `rpcd` (ubus) с ACL-разделением
  прав чтения и записи.
- **Конфигурация — UCI, живое состояние — tmpfs.** Настройки лежат в `/etc/config`, оперативные
  состояния демонов — в `/var/run`, чтобы не изнашивать флеш-память.
- **Hot-reload вместо рестартов.** Выученные правила, списки ресурсов и правки маршрутизации
  применяются перечитыванием конфигов — без обрыва установленных соединений.
- **Last-known-good для важных конфигов.** Ядро, mosdns, rule-set'ы, RU-гео: кандидат генерируется
  и проверяется рядом с рабочим, меняет файл атомарно и только после живой верификации службы
  становится новым `.lastgood`; откат — автоматический.
- **Fail-safe перехвата.** Пока TUN не поднят, маршрут «в никуда» закрыт заранее — окна утечки
  мимо перехвата нет; смерть DPI-движков или стёртые firewall-цепи означают прямой проход пакетов,
  а не потерю связи; снапшот провайдерских DNS держится последним сервером dnsmasq, чтобы имена
  резолвились даже при мёртвой прокси-DNS-цепи.
- **Сторожа и самовосстановление.** Health ведёт живые вердикты всех служб (ok / деградация /
  отказ) с причиной и уверенностью; Sentinel — независимый сторож самого мониторинга и конфигов
  с защитой от ремонтных петель; Recovery — координатор с гистерезисом, экспоненциальными
  повторами и лимитом авто-ремонтов.
- **Подписанный фид с контролем целостности.** Ядра, DPI-движки и помощники приходят из нашего
  зеркала официальных релизов апстримов с нашей подписью; файлы из фида проверяются по sha256
  из манифеста до установки.

## Ресурсы и производительность

Приложение рассчитано на слабое железо и не требует ручной настройки; ниже — что именно оно
делает, чтобы вписываться в бюджет роутера:

- **Профили ресурсов** — Авто / Эко / Сбалансированный / Производительность («Обслуживание»):
  меняют частоту опросов, глубину историй и объём выборок проб; «Эко» дополнительно сужает
  предел состояния движка самообучения (минус 10–15 МБ RAM).
- **Иерархия жертв OOM** — прокси-ядро, DPI-движки и резидентные помощники помечены
  `oom_score_adj`: при пиковом давлении памяти ядро Linux закрывает возобновляемые процессы,
  а не Wi-Fi/DNS/UI-плоскость (dnsmasq, hostapd, uhttpd, rpcd остаются на adj 0).
- **Бюджеты и Sentinel** — у каждого демона свои нормы RSS/fd; при критическом перерасходе
  прокси-ядро автоматически перезапускается раньше, чем сработает OOM-killer (пара минут
  разрыва вместо падения всей системы).
- **Мягкий предел Go-кучи на любом объёме RAM** — GOMEMLIMIT применяется ко всем боксам:
  куча прокси-ядра ограничена (384 МБ по умолчанию, и никогда больше половины физической
  памяти), поэтому пиковый рост «до OOM» невозможен в принципе.
- **Спящая вкладка не греет роутер** — свёрнутая/фоновая вкладка веб-интерфейса прекращает
  опросы до нуля и возобновляет их сразу после возврата на вкладку.
- **zram/swap — осознанно нет.** На узкофлешевых боксах выигрыша нет, а боксам с 1 ГБ RAM
  и выше запас не нужен: пиковые сценарии закрывают GOMEMLIMIT + иерархия жертв.

## Возможности

### Маршрутизация и надёжность
- **Мастер маршрутизации** — интерактивный центр: диагностика провайдера (что и как блокируется —
  напрямую/через ваши правила), «Сервисы → выходы» (каждому сервису — свой выход с живой проверкой),
  обход DPI, импорт каталогов стратегий.
- **Hot Swap** — горячий резерв для основного узла: несколько постоянно проверяемых соединений и
  переключение на живой резерв за секунды **без рестарта ядра**; анти-флап против лишних переключений.
- **URLTest с тремя режимами** — Авто / Приоритетный узел + авто / Ручной список; сторож мёртвых узлов.
- **Правила для России** — RU Proxy Rules (Russia Inside, Re:Filter) в один клик; исключение всего
  российского интернета из прокси.
- **Устойчивость прямых соединений** — отказ узла не рвёт SSH/DNS/соединения; OAuth-авторизации
  (Google/Microsoft/Apple) идут через закреплённый защищённый выход.

### Обход DPI
- **Strategy Lab** — фаззинг всего корпуса стратегий на изолированной NFQUEUE с baseline-прогоном,
  ранжированием по раундам и метриками «старт превью» и «скорость потока».
- **Автоподбор и автопилот** — подбор лучшей стратегии для YouTube/Discord одной кнопкой; автопилот
  по расписанию следит за качеством (вердикты жив/деградация/мёртв) и сам чинит сломавшуюся стратегию.
- **Композиция** — разные стратегии для разных ресурсов одновременно (профиль YouTube + профиль Discord
  + общий запасной), с серверным снапшотом и кнопкой отката.
- **Мультистратегии nfqws2** — один процесс с несколькими профилями и отдельными hostlist'ами;
  генератор собственных стратегий и редактируемый список ТСПУ (dpi-detect).

### Автоматизация и контроль
- **Движок самообучения** — находит заблокированные сайты (DNS/Clash/SNI-источники), различает тип
  блокировки (DPI / DNS-подмена / заглушка / страница отказа), самолечится и применяет выученное
  hot-reload'ом без разрыва соединений; нативные помощники (Go) для батч-проб и захвата SNI.
- **Контроль** — родительский контроль: устройства из живой сети, правила сайтов, расписания,
  Wi-Fi, журнал — и то же самое через Telegram-бота.
- **Telegram-бот v2** — статус, узлы, переключение без рестарта, снапшоты, пуш-уведомления
  (смена узла, сбои, обучение) с дедупликацией и rate-limit.

### Сеть и диагностика
- **MultiDNS (mosdns)** — каждый DNS-запрос гонится по всему пулу, побеждает самый быстрый живой ответ;
  демон качества проверяет, что возвращённые IP реально открывают сайты, и исключает мёртвые/отравленные.
- **Мониторинг узлов** — дашборд задержек и статусов, живой список соединений с поиском и фильтрами.
- **Обзор** — карточки всех подсистем, локальные SVG-графики (CPU/RAM/температура/соединения/задержка),
  трафик по выходам, быстрые действия.
- **Центр здоровья** — баннер-вердикт всей системы, таблица служб с причинами и кнопками ремонта,
  полная лента событий.
- **Диагностика** — проверки ядра, DNS, перехвата nftables, связности + отчёт для поддержки.
- **Снапшоты и восстановление** — бэкап конфигурации в один клик, аварийное «вернуть интернет напрямую».

### Режим сервера
- **Роутер как точка входа** — входящие подключения (inbounds): VLESS, Trojan, Hysteria2,
  Shadowsocks, VMess, SOCKS/HTTP (смешанный), AnyTLS, MTProxy и другие; не зависит от клиентского
  режима — можно использовать оба или ни одного.
- **Брандмауэр на каждый inbound** — по умолчанию порт доступен только из LAN; открытие в интернет —
  отдельным переключателем.
- **TLS под ключ** — свой сертификат, генерация самоподписанного в один клик или авто-выпуск
  Let's Encrypt / ZeroSSL через ACME (HTTP-01/DNS-01, на сборках с поддержкой ACME).

### Установка и обновление
- **Интерактивный установщик** — ставит приложение, ядро, подписку, Hot Swap, MultiDNS, автоматизацию
  и Zapret по шагам и **никогда не оставляет без интернета** (без подписки включается прямой режим
  и создаётся правило «YouTube → Zapret»).
- **Самообновление** — проверка и установка новой версии прямо из веб-интерфейса, без SSH.
- **Умный установщик ядер** — сам подбирает сборку под свободное место (включая компактную UPX) и
  архитектуру; асинхронная установка с прогрессом.

## Установка

Требования: OpenWrt/ImmortalWrt **24.10+** (opkg) или **25.12+** (apk). Рекомендуется ~40 МБ свободного места.

### Быстрая установка (одной командой)

```sh
wget -qO- https://raw.githubusercontent.com/ezdizzy/re-homeproxy/master/install.sh | sh
```

Интерактивный установщик проведёт по шагам: приложение + русский язык → ядро → подписка/узел →
Hot Swap → MultiDNS → Автоматизация → Zapret 2 с автотестом → автопилот → ByeDPI.
Повторный запуск скрипта открывает меню настройки. При заблокированном GitHub укажите зеркало
(переменная ставится перед `sh`):

```sh
wget -qO- https://raw.githubusercontent.com/ezdizzy/re-homeproxy/master/install.sh | GH_MIRROR=https://your.mirror sh
```

### Пакеты вручную

APK (OpenWrt 25.12+):

```sh
wget -O /tmp/homeproxy-hiddify.pub https://github.com/ezdizzy/re-homeproxy/releases/latest/download/homeproxy-hiddify.pub
cp /tmp/homeproxy-hiddify.pub /etc/apk/keys/
wget -O /tmp/app.apk "$(wget -qO- 'https://api.github.com/repos/ezdizzy/re-homeproxy/releases' | grep -o 'https://github\.com/[^"]*luci-app-ravnex[^"]*\.apk' | head -1)"
apk add /tmp/app.apk
```

opkg (OpenWrt 24.10):

```sh
wget -O /tmp/app.ipk "$(wget -qO- 'https://api.github.com/repos/ezdizzy/re-homeproxy/releases' | grep -o 'https://github\.com/[^"]*luci-app-ravnex[^"]*\.ipk' | head -1)"
opkg install /tmp/app.ipk
```

Ядро, ByeDPI, Zapret 2 и mosdns ставятся на странице **«Обслуживание» → «Управление ядром»**
веб-интерфейса — установщик сам определит архитектуру и подберёт сборку. Подробные ручные шаги — в
[вики](../../wiki/Getting-Started-ru).

### Обновление

Страница **«Обслуживание» → «Управление ядром» → Application → Проверить обновление**. Версии
сравниваются с последним релизом GitHub; обновление ставится на месте, rpcd перезапускается
автоматически. Обновления с предыдущих версий (Re:HomeProxy AutoMod 2.x) проходят без ручных
шагов — приложение уже называется Ravnex после установки новой версии.

⚠️ **Обновление с 3.0.x до 3.1.0 и новее — через [install.sh](#быстрая-установка-одной-командой),
а не кнопкой.** Релиз 3.1.0 переименовывает пакет (`luci-app-ravnex`): кнопка «Обновить» в
приложении на боксе 3.0.x честно сообщит о конфликте закреплённого старого имени в apk world
(роутер при этом не страдает), а установщик переносит приложение на новое имя корректно.

## Безопасность и приватность

- **Только LAN** — приложение не открывает портов в WAN; локальные служебные слушатели работают
  только на loopback.
- **Всё локально** — интерфейс не обращается к внешним CDN/шрифтам; графики строятся на клиенте.
- **Свой подписанный репозиторий** — все компоненты (ядра, DPI-движки, помощники) доставляются
  из нашего фида — зеркала официальных релизов апстримов с нашей подписью; сборка приложения —
  GitHub CI этого репозитория.

Проект опирается на работы открытого сообщества:

- [ImmortalWrt HomeProxy](https://github.com/immortalwrt/homeproxy) — исходное LuCI-приложение
- [hiddify-core](https://github.com/hiddify/hiddify-core) · [sing-box-extended](https://github.com/shtorm-7/sing-box-extended) · [sing-box](https://sing-box.sagernet.org) — прокси-ядра
- [zapret2 (bol-van)](https://github.com/bol-van/zapret2) и [ByeDPI (hufrea)](https://github.com/hufrea/byedpi) — обход DPI
- [Re:Filter](https://github.com/1andrevich/re-filter), [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) — списки маршрутизации
- [StressOzz/Zapret-Manager](https://github.com/StressOzz/Zapret-Manager) — каталог стратегий
- [1andrevich/homeproxy-hiddify](https://github.com/1andrevich/homeproxy-hiddify) — прямая основа ветки Re:HomeProxy

Все товарные знаки принадлежат их владельцам и упоминаются номинативно.
