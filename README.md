# Ravnex

**Own the Route.**

**Универсальная платформа управления сетевой инфраструктурой для OpenWrt.**

Маршрутизация, управление сетевыми соединениями, защищённые каналы связи, транспортные механизмы, автоматизация, мониторинг и диагностика — в единой системе с веб-интерфейсом LuCI.

Ravnex объединяет инструменты управления сетевым трафиком и инфраструктурой маршрутизатора, предоставляя централизованное управление подключениями, политиками маршрутизации, сетевыми службами и состоянием системы. Все основные компоненты работают непосредственно на устройстве, без обязательных внешних сервисов и облачной управляющей инфраструктуры.

## О проекте

**Ravnex** — это программная платформа для централизованного управления сетевой инфраструктурой маршрутизаторов OpenWrt и ImmortalWrt.

Проект объединяет несколько независимых технологических направлений в единой управляющей среде:

- **Управление сетевыми соединениями** — поддержка нескольких прокси-движков, подключений по подпискам, пользовательских конфигураций и широкого набора современных транспортных протоколов.
- **Адаптация транспортного уровня** — инструменты управления параметрами обработки сетевых соединений, каталог стратегий, лаборатория тестирования и автоматизированный подбор конфигураций.
- **Интеллектуальная маршрутизация** — распределение трафика по заданным правилам, автоматическое определение характеристик соединений и адаптация сетевых политик.
- **Отказоустойчивость** — резервирование подключений, контроль состояния узлов, автоматическое переключение и восстановление работоспособности служб.
- **Управление DNS** — параллельная проверка серверов, оценка качества ответов, раздельные пулы разрешения имён и автоматическое исключение неисправных источников.
- **Автоматизация** — сбор диагностических данных, анализ доступности сетевых ресурсов, обучение на результатах измерений и автоматическое применение проверенных конфигураций.
- **Управление доступом** — контроль подключённых устройств, пользовательские правила, расписания и централизованное управление через веб-интерфейс или Telegram.
- **Мониторинг инфраструктуры** — состояние служб, сетевых подключений, системных ресурсов, производительности и событий.

### Технологическая основа

В качестве управляющей среды используется **ucode** — нативный интерпретатор OpenWrt. Это позволяет выполнять основную логику непосредственно на маршрутизаторе, избегая необходимости разворачивать дополнительные универсальные среды исполнения.

В зависимости от задачи применяются специализированные компоненты:

| Направление | Технология |
|---|---|
| Прокси-движок | hiddify-core |
| Альтернативный прокси-движок | sing-box-extended / sing-box-extended-lite |
| Обработка сетевых пакетов | Zapret 2 (nfqws2) |
| Локальная обработка соединений | ByeDPI (ciadpi) |
| Управление DNS | mosdns |
| Системная интеграция | ucode, UCI, ubus, rpcd |
| Сетевые правила | nftables |
| Специализированные помощники | Go |

Веб-интерфейс полностью автономен: графики формируются локально, внешние CDN и сторонние библиотеки не требуются, а проверка доступности обновлений выполняется по запросу пользователя.

## Архитектура сетевого взаимодействия

Ravnex использует многоуровневую модель обработки сетевого трафика. В зависимости от заданной политики соединения распределяются между соответствующими механизмами обработки.

Основная классификация выполняется средствами **nftables**, что позволяет направлять потоки по необходимым контурам без избыточной передачи пакетов между пользовательскими процессами.

| Контур | Технология | Назначение |
|---|---|---|
| Прямая маршрутизация | nftables / системная маршрутизация | Передача трафика через стандартный сетевой стек |
| Транспортная обработка | Zapret 2 / nfqws2 | Управление параметрами обработки и последовательностью передачи сетевых пакетов |
| Локальный транспортный механизм | ByeDPI / ciadpi | Альтернативная обработка соединений через локальный SOCKS-интерфейс |
| Защищённые соединения | hiddify-core / sing-box-extended | Создание туннелей и маршрутизация через внешние узлы |
| DNS-инфраструктура | mosdns | Обработка запросов, параллельный выбор DNS-источников и контроль качества ответов |

Каждый контур может использоваться независимо от остальных. Это позволяет формировать различные профили обработки трафика, комбинировать механизмы и определять индивидуальные правила для отдельных категорий соединений.

### Поддерживаемые транспортные протоколы

Прокси-подсистема поддерживает широкий набор протоколов и механизмов подключения:

- VLESS (Reality / XHTTP);
- Hysteria2;
- VMess;
- Trojan;
- Shadowsocks;
- WireGuard / AmneziaWG;
- SSH;
- NaiveProxy;
- Mieru;
- другие протоколы, поддерживаемые выбранной сборкой ядра.

В зависимости от установленного ядра и его комплектации доступность отдельных транспортов может различаться.

## Основные принципы архитектуры

### Локальное исполнение

Основная управляющая логика и фоновые службы работают непосредственно на маршрутизаторе.

- ucode используется для управляющих процессов и фоновой автоматизации.
- Go применяется точечно для специализированных высокопроизводительных задач.
- LuCI взаимодействует с системными службами через rpcd и ubus.
- ACL обеспечивают разделение операций чтения и изменения конфигурации.

Архитектура не требует обязательного подключения к внешней управляющей платформе.

### Конфигурация и состояние

Используется разделение постоянной конфигурации и оперативного состояния:

- UCI и `/etc/config` — постоянные настройки;
- `/var/run` — временное состояние служб;
- tmpfs — промежуточные данные и оперативные рабочие файлы.

Это сокращает количество операций записи во flash-память и повышает устойчивость системы.

### Hot-reload вместо постоянных перезапусков

Изменения маршрутизации, списков ресурсов и управляющих правил по возможности применяются динамически.

Перечитывание конфигурации позволяет обновлять рабочие параметры без принудительного перезапуска всех служб и без необоснованного разрыва уже установленных соединений.

### Last-known-good

Для критически важных конфигураций используется механизм проверки и сохранения последнего заведомо рабочего состояния.

Новая конфигурация:

1. Генерируется отдельно от действующей.
2. Проходит предварительную проверку.
3. Применяется атомарной заменой.
4. Проверяется на работающей службе.
5. Сохраняется как последняя подтверждённая версия.

При обнаружении неисправности система возвращается к предыдущему рабочему состоянию.

### Fail-safe и отказоустойчивость

Архитектура предусматривает безопасное поведение при отказе отдельных компонентов:

- До готовности TUN-интерфейса блокируется преждевременное направление трафика в неработающий маршрут.
- При отказе транспортных обработчиков предусмотрен возврат к штатной маршрутизации.
- При нарушении работы firewall предусмотрены механизмы восстановления сетевых правил.
- Сохраняется резервная информация о DNS-параметрах провайдера.
- Аварийное восстановление стандартной маршрутизации доступно из веб-интерфейса.

Цель этих механизмов — сохранить работоспособность базовой сетевой инфраструктуры даже при частичном отказе управляющих компонентов.

### Мониторинг и самовосстановление

Система использует несколько независимых уровней контроля:

- **Health** — собирает состояние служб и формирует диагностические вердикты.
- **Sentinel** — контролирует работу механизмов мониторинга и целостность конфигураций.
- **Recovery** — координирует восстановление, управляет повторными попытками и предотвращает бесконечные циклы ремонта.

Состояния компонентов классифицируются как нормальная работа, деградация или отказ с указанием причины и степени уверенности.

### Контроль целостности компонентов

Системные компоненты распространяются через собственный репозиторий Ravnex, содержащий сборки и зеркала официальных релизов используемых проектов.

Пакеты сопровождаются манифестами и контрольными суммами SHA-256. Перед установкой выполняется проверка целостности загружаемых файлов.

## Функциональные возможности

### 1. Управление маршрутизацией и соединениями

- **Мастер маршрутизации** — единый центр настройки сетевых политик, диагностики соединений и управления транспортными механизмами.
- **Назначение выходов** — индивидуальный выбор способа обработки трафика для различных категорий приложений и сетевых ресурсов.
- **Hot Swap** — система резервирования основных подключений с несколькими постоянно проверяемыми соединениями и автоматическим переключением на работоспособный резерв без перезапуска ядра.
- **URLTest** — три режима выбора узлов: автоматический, приоритетный с резервированием и ручной список.
- **Контроль состояния узлов** — обнаружение отказов, деградации качества соединения и нестабильности подключений.
- **Пользовательские политики** — создание собственных правил распределения трафика.
- **Готовые наборы правил** — импорт и применение каталогов маршрутизации, включая RU Proxy Rules (Russia Inside, Re:Filter).
- **Закрепление служебных соединений** — возможность назначать отдельные маршруты для критически важных системных и авторизационных процессов.

### 2. Транспортные механизмы и адаптация соединений

Ravnex объединяет несколько инструментов обработки сетевого трафика, позволяя выбирать и комбинировать подходящие механизмы в зависимости от характеристик сети и используемого оборудования.

**Strategy Lab**

Изолированная среда тестирования транспортных конфигураций:

- проверка каталога стратегий;
- фаззинг и сравнение параметров обработки;
- выполнение тестов через изолированную NFQUEUE;
- контрольный baseline-прогон;
- поэтапное ранжирование результатов;
- измерение времени установления соединения и скорости передачи данных.

**Автоматический подбор параметров**

- подбор конфигураций для выбранных категорий сетевых ресурсов;
- сравнение результатов нескольких стратегий;
- определение работоспособных вариантов;
- автоматическое применение выбранной конфигурации;
- контроль качества после применения.

**Автопилот**

Периодически проверяет действующие настройки, выявляет деградацию и при необходимости предлагает или применяет альтернативную конфигурацию.

**Композитные профили**

Позволяют одновременно использовать разные параметры обработки для различных категорий соединений с общим резервным профилем.

Поддерживается серверный снапшот текущей конфигурации и быстрое восстановление предыдущего состояния.

**Дополнительные возможности**

- несколько профилей nfqws2 в рамках одного процесса;
- независимые hostlist для разных категорий трафика;
- генератор пользовательских стратегий;
- редактируемые списки диагностических сигнатур;
- поддержка ByeDPI с каталогом из 47 готовых пресетов и собственным тестером стратегий.

### 3. Интеллектуальная автоматизация

Встроенный движок автоматизации анализирует характеристики сетевых соединений и помогает адаптировать политики маршрутизации к изменяющимся условиям сети.

Основные возможности:

- обнаружение ресурсов с нестабильной или ограниченной связностью;
- анализ результатов DNS-запросов;
- проверка соединений различными транспортными механизмами;
- сбор и сопоставление диагностических признаков;
- классификация характера сетевых ошибок;
- выявление изменений в поведении соединений;
- формирование новых правил на основании результатов измерений;
- автоматическое применение проверенных изменений через hot-reload.

Для повышения производительности используются специализированные Go-помощники, выполняющие пакетные проверки и сбор сведений о сетевых соединениях, включая анализ SNI.

Движок сохраняет результаты предыдущих измерений, что позволяет учитывать историю качества соединений и избегать необоснованных изменений конфигурации.

### 4. DNS-инфраструктура

**MultiDNS** построен на базе mosdns и предназначен для повышения устойчивости разрешения доменных имён.

- Параллельное выполнение запросов через доступные DNS-источники.
- Выбор наиболее быстрого работоспособного ответа.
- Раздельные пулы обычных и защищённых DNS-серверов.
- Мониторинг доступности и качества ответов.
- Проверка фактической связности с полученными адресами.
- Автоматическое исключение неисправных источников.
- Возврат ранее исключённых серверов после восстановления.
- Резервирование параметров системного DNS.

Система оценивает не только время ответа DNS-сервера, но и практическую пригодность полученных результатов.

### 5. Управление доступом и автоматизация через Telegram

Встроенные инструменты позволяют управлять сетевой средой без постоянного доступа к веб-интерфейсу.

**Родительский контроль:**

- обнаружение устройств в локальной сети;
- индивидуальные правила для устройств;
- управление доступом к сетевым ресурсам;
- расписания;
- управление Wi-Fi;
- журнал событий;
- удалённое управление через Telegram.

**Telegram Bot v2:**

- получение состояния системы;
- просмотр подключений и узлов;
- переключение активного подключения без перезапуска ядра;
- создание и восстановление снапшотов;
- уведомления об изменении состояния служб;
- сообщения о событиях автоматизации;
- контроль повторных уведомлений через дедупликацию и rate-limit.

### 6. Мониторинг и диагностика

Ravnex предоставляет централизованный интерфейс наблюдения за состоянием маршрутизатора и его сетевых компонентов.

**Главная панель:**

- состояние подсистем;
- загрузка CPU;
- использование RAM;
- температура устройства;
- количество соединений;
- задержки;
- статистика трафика по выходам;
- быстрые действия.

**Мониторинг узлов:**

- задержки и доступность;
- динамические статусы;
- список активных соединений;
- поиск и фильтрация.

**Центр здоровья:**

- общий вердикт состояния системы;
- состояние каждой службы;
- описание выявленных проблем;
- уровень деградации;
- доступные действия восстановления;
- полная история событий.

**Диагностический модуль:**

- проверка прокси-ядра;
- тестирование DNS;
- проверка правил nftables;
- анализ сетевой связности;
- контроль состояния транспортных механизмов;
- формирование диагностического отчёта для технической поддержки.

**Снапшоты и восстановление:**

- резервное копирование конфигурации;
- восстановление предыдущего состояния;
- аварийный возврат к стандартной маршрутизации;
- контроль целостности конфигурационных данных.

### 7. Режим сервера

Помимо управления исходящими соединениями, Ravnex позволяет использовать маршрутизатор в качестве точки входа для внешних подключений.

Поддерживаемые inbound-протоколы:

- VLESS;
- Trojan;
- Hysteria2;
- Shadowsocks;
- VMess;
- SOCKS / HTTP (смешанный вход);
- AnyTLS;
- MTProxy;
- другие механизмы, доступные в используемой сборке ядра.

Серверный режим независим от клиентской конфигурации. Оба режима могут использоваться одновременно, по отдельности или отключаться полностью.

**Управление безопасностью входящих подключений:**

- отдельные настройки для каждого inbound;
- ограничение доступа к локальной сети по умолчанию;
- индивидуальное управление доступностью портов из внешней сети;
- настройка TLS;
- генерация самоподписанных сертификатов;
- выпуск и обновление сертификатов через ACME;
- поддержка Let's Encrypt и ZeroSSL;
- HTTP-01 и DNS-01 (при наличии соответствующей поддержки в сборке).

### 8. Установка и обновление

**Интерактивный установщик**

Автоматически проводит пользователя через основные этапы первоначальной настройки:

1. Установка приложения и языковых компонентов.
2. Выбор и установка прокси-ядра.
3. Импорт подписки или добавление подключения.
4. Настройка Hot Swap.
5. Настройка MultiDNS.
6. Подключение автоматизации.
7. Установка Zapret 2 и первичная проверка конфигурации.
8. Настройка автопилота.
9. Установка и настройка ByeDPI.

## Производительность и использование ресурсов

Ravnex разрабатывается с учётом ограниченных вычислительных ресурсов маршрутизаторов. Архитектура ориентирована на минимизацию фоновой нагрузки, сокращение лишних операций и предсказуемое поведение при ограниченном объёме оперативной памяти.

### Профили производительности

В разделе «Обслуживание» доступны четыре профиля:

- **Авто** — автоматическое управление параметрами нагрузки.
- **Эко** — минимизация фоновой активности и потребления памяти.
- **Сбалансированный** — компромисс между частотой мониторинга и использованием ресурсов.
- **Производительность** — повышенная интенсивность проверок и расширенные диагностические выборки.

Профили изменяют частоту опросов, глубину исторических данных, объём выборок и ограничения внутреннего состояния автоматизации.

Экономичный режим дополнительно сокращает объём памяти, используемый движком самообучения, ориентировочно на 10–15 МБ.

### Управление памятью

- Для фоновых служб предусмотрена иерархия `oom_score_adj`.
- При дефиците памяти возобновляемые процессы имеют более высокий приоритет на завершение, чем базовые сетевые службы.
- DNS, Wi-Fi и управляющая плоскость защищены от необоснованного вытеснения.
- Для служб определены индивидуальные бюджеты RSS и файловых дескрипторов.
- Sentinel контролирует перерасход ресурсов.
- При критическом росте потребления памяти предусмотрено управляемое восстановление прокси-ядра.

### Ограничение памяти Go

Для Go-компонентов применяется `GOMEMLIMIT`.

Это позволяет контролировать рост используемой памяти и ограничивать размер кучи с учётом объёма физической RAM устройства.

Для прокси-ядра предусмотрен лимит 384 МБ по умолчанию с дополнительным ограничением относительно физической памяти.

### Минимизация фоновой активности

Свёрнутая или неактивная вкладка интерфейса прекращает регулярные запросы мониторинга. При возвращении на страницу обновление данных возобновляется автоматически.

Это позволяет не расходовать вычислительные ресурсы маршрутизатора на обновление интерфейса, которым в данный момент никто не пользуется.

### Отказ от обязательного swap

Ravnex не требует обязательной настройки zram или swap.

Основная стратегия управления памятью строится на ограничении потребления, контроле фоновых процессов и управляемом восстановлении служб.

## Установка

**Системные требования:**

- OpenWrt / ImmortalWrt 24.10+ (opkg).
- OpenWrt / ImmortalWrt 25.12+ (apk).
- Рекомендуется около 40 МБ свободного пространства для установки приложения. Дополнительные компоненты требуют собственного места.

### Быстрая установка

```sh
wget -qO- https://raw.githubusercontent.com/ezdizzy/ravnex/master/install.sh | sh
```

Интерактивный установщик проведёт через основные этапы установки и настройки компонентов.

Повторный запуск скрипта открывает меню управления установкой.

При использовании зеркала GitHub:

```sh
wget -qO- https://raw.githubusercontent.com/ezdizzy/ravnex/master/install.sh | GH_MIRROR=https://your.mirror sh
```

### Ручная установка пакетов

**APK (OpenWrt 25.12+):**

```sh
wget -O /tmp/homeproxy-hiddify.pub https://github.com/ezdizzy/ravnex/releases/latest/download/homeproxy-hiddify.pub

cp /tmp/homeproxy-hiddify.pub /etc/apk/keys/

wget -O /tmp/app.apk "$(wget -qO- 'https://api.github.com/repos/ezdizzy/ravnex/releases' | grep -o 'https\://github\.com/[^"]*luci-app-ravnex[^"]*\.apk' | head -1)"

apk add /tmp/app.apk
```

**opkg (OpenWrt 24.10):**

```sh
wget -O /tmp/app.ipk "$(wget -qO- 'https://api.github.com/repos/ezdizzy/ravnex/releases' | grep -o 'https\://github\.com/[^"]*luci-app-ravnex[^"]*\.ipk' | head -1)"

opkg install /tmp/app.ipk
```

Прокси-ядра, транспортные компоненты и mosdns устанавливаются отдельно через раздел:

**Обслуживание → Управление ядром**

Установщик определяет архитектуру устройства и подбирает подходящую сборку.

Подробная документация: [Getting Started](../../wiki/Getting-Started-ru).

### Обновление

Проверка обновлений доступна в интерфейсе:

**Обслуживание → Управление ядром → Application → Проверить обновление**

Обновление устанавливается непосредственно на устройстве. Необходимые управляющие службы перезапускаются автоматически.

Переход с предыдущих версий Re:HomeProxy AutoMod 2.x поддерживается штатным механизмом миграции.

**Важно:** обновление с версии 3.0.x до 3.1.0 и новее необходимо выполнять через `install.sh`, а не через кнопку обновления приложения.

В версии 3.1.0 изменено имя системного пакета на `luci-app-ravnex`. Установщик корректно выполняет миграцию со старого имени пакета.

## Безопасность и конфиденциальность

Ravnex следует принципу локального управления: основные операции выполняются непосредственно на оборудовании пользователя.

**Изоляция управляющей среды**

- Веб-интерфейс предназначен для использования из локальной сети.
- Приложение самостоятельно не открывает входящие порты WAN.
- Локальные служебные интерфейсы привязываются к loopback, если их назначение не требует иного.
- Взаимодействие между интерфейсом и фоновыми службами осуществляется через rpcd/ubus с разграничением разрешений.

**Локальная обработка данных**

- Внешние CDN и сторонние облачные интерфейсы не используются.
- Графики и визуализация формируются непосредственно в браузере.
- Оперативное состояние хранится локально.
- Внешняя управляющая платформа не требуется для штатной работы.

**Целостность компонентов**

- Используется собственный репозиторий релизов.
- Загружаемые компоненты сопровождаются контрольными суммами.
- Перед установкой выполняется проверка целостности.
- Сборка приложения автоматизирована через GitHub Actions.

**Контроль пользователя**

Пользователь самостоятельно определяет подключаемые узлы, конфигурации, политики маршрутизации, сетевые правила и параметры внешней доступности.

Отдельные функции, связанные с получением обновлений, загрузкой компонентов и использованием внешних транспортных узлов, предполагают соответствующие сетевые обращения. Их параметры и условия определяются выбранной конфигурацией.
