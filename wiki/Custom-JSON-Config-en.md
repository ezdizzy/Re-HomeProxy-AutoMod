# Custom JSON config (removed in v3)

The **Custom JSON** routing mode was removed in v3. It cluttered the core functionality: a raw
config bypassing the generator broke the reliability invariants — last-known-good, interception
control, and honest page statuses. The decision is recorded in the v3 plan (D23).

---

## What to use instead

- **[Advanced rules (expert)](Custom-Routing-en)** — routing nodes and raw sing-box rules with
  the highest priority, straight from the UI. This covers most «I need a field the forms lack»
  scenarios.
- **[Service rules](Routing-Master-en)** — service → exit, host pins and the live route check.
- **[DNS settings](DNS-Settings-en)** — separate plain/secure pools, MultiDNS.

The core config (`/etc/homeproxy/hiddify-c.json`) is fully generated by the app and protected by
the last-known-good pipeline: a broken config never reaches production, and if something breaks
after the start — an automatic rollback and restart (see
[Hot Swap and reliability](Hot-Swap-and-Reliability-en)).
