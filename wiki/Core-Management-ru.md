# Управление ядром

Ravnex **многоядерный**: приложение LuCI — это интерфейс, а само проксирование выполняет
отдельный бинарник-**ядро**. Установка, обновление и переключение ядер — на странице
**Обслуживание → Управление ядром** — без SSH.

---

## Источники — только оригиналы

Все ядра устанавливаются **напрямую из оригинальных репозиториев** их разработчиков:

- **hiddify-core** → релизы [hiddify/hiddify-core](https://github.com/hiddify/hiddify-core)
  (оригинальные OpenWrt-пакеты apk/ipk; тарбол — резервный путь);
- **sing-box-extended** → релизы [shtorm-7/sing-box-extended](https://github.com/shtorm-7/sing-box-extended)
  (apk/ipk; для малой флеш — оригинальный UPX-сжатый тарбол);
- **sing-box-extended-lite** → релизы [MANCrimSon/sing-box-extended-lite](https://github.com/MANCrimSon/sing-box-extended-lite)
  (тарболы Pure/UPX; их собственный установщик остаётся резервным путём).

Каждая загрузка проверяется по **SHA256** (digest ассета из GitHub API) до установки.
Молчаливый даунгрейд запрещён: более старую версию можно поставить только явно —
кнопкой **«Откатить»** на карточке ядра.

## Выбор ядра

| | **hiddify-core** (по умолчанию) | **sing-box-extended** |
|---|---|---|
| Движок | hiddify-core v5.x (база sing-box 1.15) | Расширенная база sing-box (shtorm-7) |
| Размер | Крупный (~101 МБ бинарника) | Крупнее (~26 МБ установленного); есть UPX-сборка |
| Протоколы приложения | Все протоколы, которые умеет настраивать приложение | Все протоколы, которые умеет настраивать приложение |
| **NaïveProxy** | ✅ **Поддерживается** | ❌ **Нет** (такие узлы **пропускаются автоматически**) |
| **AmneziaWG** | ✅ Поддерживается | ✅ Поддерживается |
| **WARP / MASQUE / TrustTunnel** | ❌ Приложением не используются | ✅ Есть в ядре |

**Правило:** оба ядра работают со всеми протоколами приложения — практическая разница в
**NaïveProxy** (только hiddify-core). Если в подписке есть NaïveProxy-узлы — оставайтесь на
hiddify-core. При переключении на sing-box-extended неподдерживаемые узлы автоматически
исключаются из всех пулов (приложение покажет какие). Есть и **lite-ядро**
(sing-box-extended-lite) для устройств с очень малой flash.

Какие протоколы появятся в редакторе узлов — зависит от установленного ядра; см.
[Поддерживаемые протоколы](Supported-Protocols-ru).

## Установка — умный установщик

Селектор сборки (для тех ядер, у которых он есть): **Авто / Полная / UPX**. В «Авто»
установщик проверяет устройство и подбирает сборку, которая действительно поместится:

1. Считывает свободное место на `/overlay` (постоянная флеш-память) и свободную ОЗУ.
2. Если полная сборка помещается → ставит **стандартную**. Если места мало, но ОЗУ хватает
   (и UPX-сборка у этого ядра существует) → ставится **компактная (UPX)** с честной пометкой.
3. Если не помещается ни одна → останавливается с понятным сообщением, а не ставит заведомо
   нерабочее.

У **hiddify-core** компактной UPX-сборки не существует (оригинал её не публикует) — предлагается
только полная сборка. UPX-варианты есть у **sing-box-extended** и **lite**; на soft-float MIPS
UPX ненадёжен, поэтому «Авто» никогда не выбирает его там — только явный выбор.

**Компактная сборка (UPX)** занимает гораздо меньше места на флеше, но **распаковывается в ОЗУ
при каждом запуске**. На большинстве роутеров в повседневной работе это незаметно.

Установка **асинхронная, с живым статусом** — страница остаётся отзывчивой (большая загрузка
не замораживает вкладку). После установки установщик сам проверяет новое ядро и перезапускает
службу.

## Память — кратко

| Свободно на `/overlay` | Что устанавливается |
|---|---|
| ~110 МБ+ | hiddify-core (полная оригинальная сборка) |
| ~40 МБ+ | sing-box-extended (полная) или его UPX-сборка (если хватает ОЗУ) |
| < ~25 МБ | Недостаточно — освободите место или запеките ядро в собственный образ прошивки |

> На сжимающем overlay (jffs2/ubifs) полной сборке нужно меньше свободного места, чем сырая
> цифра. Установщик учитывает это автоматически — доверяйте его проверке, а не таблице.

## Переключение ядер и обновление

- **Обновление:** нажмите **Установить** снова — будет загружен и переустановлен последний
  релиз оригинала.
- **Откат:** кнопка **«Откатить»** на карточке ядра показывает последние релизы оригинала;
  выбранный релиз скачивается заново, проверяется по SHA256 и ставится как ЯВНЫЙ даунгрейд
  (только это подтверждение обходит запрет молчаливого даунгрейда). На роутере ничего не
  кэшируется — архив удаляется сразу после установки.
- **Переключение ядер:** установите другое ядро; если присутствуют оба, используется настройка
  **Предпочитаемое ядро** (страница «Подключение»). Генератор конфигурации и служба учитывают
  одну и ту же настройку.
- **Версия / статус:** раздел показывает установленное ядро и версию.

Приложение, mosdns, хелперы и наши apk/ipk-сборки движков приходят из **нашего подписанного
источника пакетов**; сами ядра — только из оригиналов: детали и карточка
«Источник обновлений»: [Установка и обновление](Installation-and-Updates-ru).

## Rule-set'ы — страховка холодного старта

Карточка **«Rule-set'ы»** качает локальные копии `.srs` для каждого rule-set (имя = тег). Когда
папка локальных копий существует, каждый remote rule-set получает локальную копию для первой
загрузки: холодный старт без работающего интернета (свежая прошивка, DPI-блок GitHub) больше
не убивает ядро с «FATAL initialize rule-set». Списки по-прежнему обновляются из сети раз в
сутки в фоне.

## Ресурсы и модули ядра

- RU-списки маршрутизации и гео-базы **обновляются сами** по расписанию; подписки обновляются
  отдельно — см. [Подписки и импорт узлов](Subscriptions-ru).
- Для прозрачной маршрутизации нужны `kmod-nft-tproxy` и `kmod-tun` — установщик подтягивает их.
