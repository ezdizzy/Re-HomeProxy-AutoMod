# Маршрутизация и контроль доступа

Страница **«Подключение»** решает, **куда** уходит трафик: основной узел, режим маршрутизации
и то, что держит связь при смерти сервера (выход-движок, URLTest, Hot Swap). Новые серверы
добавляются на странице [«Серверы»](Subscriptions-ru).

---

## Режимы маршрутизации

Три режима — простых и непересекающихся:

| Режим | Что делает |
|---|---|
| **Обход блокировок (по спискам правил)** | Повседневный **рабочий** режим: всё идёт напрямую, а трафик, попавший в [Правила для сервисов](Routing-Master-ru), идёт через назначенный выход. Здесь работают движки обхода (Zapret / ByeDPI) и движок автоматизации. |
| **Всё через узел** | Весь трафик через Основной узел; правила для отдельных сервисов не используются. |
| **Напрямую (все механизмы выключены)** | Режим ремонта и диагностики: перехват, движки, схема DNS и само ядро выключены — роутер раздаёт интернет ровно так, как его даёт провайдер. |

При смене режима страница перестраивается и остаются только относящиеся к режиму настройки.
Устаревшие значения старых версий мигрируют в рабочий режим автоматически при старте службы
(с честным предупреждением).

**Порты маршрутизации** — ограничить, какие порты назначения проксируются (например,
*только типичные порты*, чтобы P2P шёл напрямую).

**Режим прокси** — как перехватывается трафик: `Redirect TCP`, `Redirect TCP + TProxy UDP`
(по умолчанию), режимы TUN (требуют `kmod-tun`).

## Выход-движок (Основной узел)

Один движок владеет выходом для **всех** режимов. Три режима работы:

| Режим | Поведение |
|---|---|
| **Авто** — лучший узел | Держит лучший узел и переезжает, только когда другой стабильно быстрее (допуск × несколько раундов подряд) |
| **Приоритетный узел** | Держит выбранный узел, пока он отвечает; уходит только при реальной смерти; возвращается после восстановления |
| **Ручной** | Держит выбранный вами узел |

Ключевые настройки:

- **Резервные узлы** — приоритетный порядок фолбэка; резервы простукиваются живьём (тоннели
  тёплые), это и есть **Hot Swap** — см. [Hot Swap и надёжность](Hot-Swap-and-Reliability-ru);
- **Интервал теста / проб** — как часто проверяются узлы и активный выход;
- **Допуск переключения** — минимальная разница задержек для переезда (анти-флап);
- **Возврат после восстановления** (failback) и **Апгрейд на лучший узел**;
- продвинутые пороги: Dead threshold, Recovery probes/window, Auto hysteresis.

Состояние движка видно на странице: активный узел, режим, число переключений, «failback on /
anti-flap on».

### Отдельный UDP-выход

По умолчанию UDP идёт за TCP. Поле **Основной UDP-узел** позволяет отправить UDP/QUIC (игры,
звонки) через другой выход — вплоть до ByeDPI/Zapret. «Как основной узел» возвращает единый
маршрут.

## Контроль доступа — каких устройств это касается

Пер-девайс политика переехала на отдельную страницу **[«Контроль доступа»](Access-Control-ru)**:
режим прокси на карточке устройства (Авто/Напрямую/Через прокси/Gaming/Глобальный), честные
бейджи, правила сайтов, Wi-Fi и расписания.

**WAN IP Policy** (принудительно проксировать/отправить напрямую конкретные IP назначения) и
**Interface Control** — свёрнутая секция внизу страницы «Подключение».

---

## OAuth-устойчивость

Авторизации Google/Microsoft/Apple идут через **закреплённый защищённый выход** — входы не
«слетают» при смене IP/узла. Подробнее: [Hot Swap и надёжность](Hot-Swap-and-Reliability-ru).

---

## Советы

- В рабочем режиме начните с **Russia Inside + Re:Filter** на странице «Правила для сервисов»;
  добавляйте сервисные списки, только если конкретный сайт всё ещё работает плохо.
- Если сайт *троттлится* (медленный), а не *заблокирован*, направьте его через
  [ByeDPI](ByeDPI-ru) или [Zapret](Zapret-ru) вместо VPN.
- Реальный маршрут любого сайта проверяется кнопкой «Проверить маршрут» на странице
  «Правила для сервисов».
