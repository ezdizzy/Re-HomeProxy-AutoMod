# Настройки DNS

Отдельная страница меню (**Настройки DNS**), где собраны все настройки DNS. Три вкладки:

## DNS-серверы

Два пула, на которых построена split-маршрутизация рабочего режима:

| Список | Назначение |
|---|---|
| **DNS-серверы России 🔓** | Резолвят российские/обычные домены **напрямую**, без прокси |
| **Защищённые DNS-сервера 🔒** | Резолвят заблокированные домены **через прокси** по шифрованному каналу (DoH/DoT) |

Можно добавлять несколько записей в каждый список. Без MultiDNS используется первая запись; с MultiDNS гоняются все.

## Резервный DNS (Reserve DNS)

Механизм для схем **без MultiDNS**: демон следит за **первым сервером каждого списка выше**; если он перестаёт отвечать — здоровый сервер из того же списка переставляется первым (все записи сохраняются). Два подфлага позволяют включить проверку отдельно для обычного и защищённого пула; проверяются только обычные UDP/Do53 серверы, DoH/DoT считаются всегда доступными.

> ⚠️ Игнорируется при включённом MultiDNS — он уже опрашивает все серверы каждого пула на каждом запросе. Используйте что-то одно.

## MultiDNS

Движок гонки DNS ([mosdns](https://github.com/IrineSistiana/mosdns)): каждый запрос параллельно отправляется всем серверам пула, побеждает самый быстрый валидный ответ. Отдельный демон качества:

- проверяет по HTTPS, что возвращённые IP реально открывают сайт;
- ведёт скользящую оценку сервера (открываемость + задержка + успешность);
- исключает (prune) стабильно плохие серверы из живого пула и автоматически возвращает их после восстановления;
- чёрный список «мёртвых» IP с автоочисткой.

Опции: гонка обычного пула, гонка защищённого пула, туннелирование защищённого пула через прокси, интервал проверки качества. Ниже — живой монитор: оценка, задержка, % открываемости у каждого сервера и кнопки Rebuild pools / Reset trends / Disable & restore DNS.

Установка/обновление движка mosdns — карточка **MultiDNS / mosdns** на странице [Управления ядром](Core-Management-ru).

## Как это работает внутри (несколько принципов)

- **Гонка concurrent:3** — пул опрашивается волнами по три сервера, а не сотней соединений
  разом: быстрых ответов достаточно, чтобы побеждать, а нагрузка на роутер остаётся маленькой.
- **Блокировщик ≠ отравление.** Ответ заглушки AdGuard-класса («site is blocked») — это
  *валидный* DNS-ответ от живого сервера, поэтому гонка его выберет, если он быстрый. Отсюда
  правило: если сайт открывается страницей «заблокировано», проверьте, не стоит ли блокирующий
  фильтр (AdGuard и т. п.) в защищённом пуле, — гонка честна, сервер не «отравленный», он
  фильтрует по своей политике.
- **Null-ответы и prune**: серверы, стабильно возвращающие мусор (пустые/заглушечные ответы на
  живые домены), вырезаются демоном качества автоматически — их оценки видны в мониторе.
- **Связь с режимами**: MultiDNS ускоряет DNS-пулы режимов «Обход блокировок» и региональных
  пресетов. В «Всё через узел» его слушатели никто не спрашивает (mosdns там не запускается) —
  держите выключенным; в «Напрямую» не работает ничего.
