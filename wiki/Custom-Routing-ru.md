# Расширенные правила (эксперт)

Свёрнутая эксперт-группа на странице **[«Правила для сервисов»](Routing-Master-ru)** — для тех,
кто знает, что делает. Здесь два инструмента:

1. **Узлы маршрутизации (Routing Nodes)** — именованные исходящие, на которые могут указывать
   правила;
2. **Сырые правила (Raw custom rules)** — сырые sing-box-правила с наивысшим приоритетом.

> Прежнего режима «Пользовательская маршрутизация» в v3 нет — его возможности переехали сюда.

---

## Узлы маршрутизации

**Узел маршрутизации** — именованный outbound, на который могут указывать правила. Редактор
виден всегда (в эксперт-группе), генератор учитывает эти узлы:

- конкретный **узел** или **URLTest** (авто-выбор самого быстрого из пула);
- свой **Резолвер доменов** (включая серверы Россия 🔓 / Защищённый 🔒);
- **Стратегия доменов** (только IPv4, предпочитать IPv6 и т. п.).

Это позволяет вещи вроде «это правило → узел A, но домены резолвить защищённым DNS».

---

## Сырые правила

Флаг **«Сырые правила (эксперт)» 👨‍💻** включает редактор сырых sing-box-правил. Правила
выпускаются с **НАИВЫСШИМ приоритетом** — выше всех строк-пресетов и пользовательских списков.
Это для форм, которые пресеты и узлы маршрутизации не строят; писать их стоит, только если вы
знаете схему правил sing-box. Флаг вступает в силу по Save & Apply.

### Поля сопоставления (сырые правила)

| Группа | Сопоставление по |
|---|---|
| Прочие поля | **Протокол** (по сниффингу — BitTorrent, DNS, QUIC, TLS, HTTP, STUN, SSH, RDP, DTLS…), версия IP, сеть, rule-set'ы |
| Хост/IP | `domain` / `domain_suffix` / `domain_keyword` / `domain_regex`, IP CIDR назначения и источника |
| Порты | порт и диапазоны портов назначения / источника |
| Процесс | имя / путь процесса (для трафика с самого роутера) |

Логика сопоставления — внутри категории ИЛИ, между категориями И; правила проверяются сверху
вниз, срабатывает первое совпавшее. Поля один-в-один соответствуют route-правилу sing-box:

- [Route](https://sing-box.sagernet.org/configuration/route/) — как устроена маршрутизация
- [Route Rule](https://sing-box.sagernet.org/configuration/route/rule/) — все поля сопоставления
- [Sniff](https://sing-box.sagernet.org/configuration/route/sniff/) — сопоставление по протоколу
  требует сниффинга (включён по умолчанию)

## Проверка маршрута

Кнопка **«Проверить маршрут»** на странице «Правила для сервисов» отвечает для введённого
сайта: какое правило выиграло в **живом** конфиге, цепочка выходов и вердикт защиты. Remote
rule-set'ы матчит само ядро, поэтому их точный состав честно помечается как «вероятно».
