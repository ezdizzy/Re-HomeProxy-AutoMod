# Пользовательский JSON конфиг (удалён в v3)

Режим маршрутизации **«Пользовательский JSON»** удалён в v3. Он «мусорил основной функционал»:
сырой конфиг в обход генератора ломал инварианты надёжности — last-known-good, контроль
перехвата и честные статусы страниц. Решение зафиксировано в плане v3 (D23).

---

## Что использовать вместо него

- **[Расширенные правила (эксперт)](Custom-Routing-ru)** — узлы маршрутизации и сырые
  sing-box-правила с наивысшим приоритетом прямо из интерфейса. Это покрывает большинство
  сценариев «мне нужно поле, которого нет в формах».
- **[Правила для сервисов](Routing-Master-ru)** — сервис → выход, закрепления хостов и живая
  проверка маршрута.
- **[Настройки DNS](DNS-Settings-ru)** — раздельные пулы plain/secure, MultiDNS.

Конфиг ядра (`/etc/homeproxy/hiddify-c.json`) полностью генерируется приложением и защищён
last-known-good-конвейером: битый конфиг не попадает в работу, а при поломке после старта —
автоматический откат и рестарт (см. [Hot Swap и надёжность](Hot-Swap-and-Reliability-ru)).
